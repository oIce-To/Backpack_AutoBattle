# Backpack AutoBattle 개발 시작점

## 현재 마일스톤

첫 번째 목표는 완성된 게임 화면이 아니라 아래 규칙을 신뢰할 수 있게 만드는 것이다.

1. 여러 칸을 차지하는 아이템을 가방에 배치한다.
2. 아이템을 90도 단위로 회전한다.
3. 범위를 벗어나거나 다른 아이템과 겹치는 배치를 거부한다.
4. 실패한 이동은 기존 배치를 보존한다.
5. 상하좌우로 맞닿은 아이템을 찾는다.

관련 런타임 코드는 `Assets/_Project/Scripts/Core/Inventory`에 있고, 검증 코드는
`Assets/_Project/Tests/EditMode`에 있다.

## Unity에서 확인하기

1. Unity에서 프로젝트를 연다.
2. `Window > General > Test Runner`를 연다.
3. `EditMode` 탭에서 `Run All`을 선택한다.
4. `BackpackGridTests`의 테스트가 모두 통과하는지 확인한다.

## 현재 프로토타입 실행하기

1. `Assets/Scenes/Prototype_Backpack.unity` 씬을 연다.
2. Unity 상단의 Play 버튼을 누른다.
3. 아이템을 좌클릭으로 드래그해 이동한다.
4. 아이템을 우클릭하거나 선택 후 `R`을 눌러 회전한다.
5. 왼쪽 상점 카드에서 아이템 종류, 희귀도, 가격과 형태를 확인한다.
6. 상점 카드를 가방으로 드래그해 놓으면 즉시 구매·배치되는지 확인한다.
7. 상점 카드를 하단 자유 보관함으로 드래그해 구매한 뒤, 보관함 안에서 자유롭게 위치를 바꿔본다.
8. 보관함의 아이템을 가방으로 드래그해 배치한다. 보관함에는 개수 제한이 없다.
9. 가방 또는 보관함 아이템을 드래그하면 상점 전체에 판매가가 표시된다. 상점 안에 놓아 판매한다.
10. `새로고침 1G` 버튼으로 현재 라운드 확률에 따라 진열을 갱신한다.
11. 상점 카드, 가방 또는 보관함 아이템 위에 마우스를 올려 툴팁의 이름·희귀도·다섯 기본 스탯·설명을 확인한다.
12. 오른쪽 `전투 시작` 버튼을 누르면 상점이 숨겨지고 전투 전용 화면으로 전환된다.
13. 왼쪽 내 6×6 가방과 오른쪽 고블린의 3×3 가방을 확인한다. 주기가 있는 아이템은 옅은 색으로 시작하고 아래에서 위로 원래 색이 차오른다.
14. 양쪽 체력바, 피해 표시, 명중/빗나감/치명타 로그를 확인한다. 전투 아이템에 마우스를 올리면 실제 전투 스탯을 툴팁으로 볼 수 있다.
15. 승리 후 `상점으로 · +5G`를 누르면 다음 라운드 수입을 받고 상점으로 돌아온다.
16. 패배 또는 시간 초과 시 `상점으로 돌아가기`를 눌러 같은 라운드에서 재배치·재도전한다.

왼쪽 `테스트 다음 +5G`는 전투를 건너뛰는 기존 테스트 기능이다. 씬의
`Backpack Prototype > Enable Debug Round Advance`를 끄면 숨길 수 있다.

배치 가능한 위치는 초록색, 불가능한 위치는 빨간색으로 표시된다. 불가능한
위치에 놓은 아이템은 드래그 이전 위치와 회전 상태로 복귀한다.

## ItemData 에셋

프로토타입 아이템 정의는 `Assets/_Project/Data/Items`에 있다. 각 에셋에서 ID,
이름, 설명, 분류, 희귀도, 가격, 표시 색상, 회전 가능 여부와 점유 칸을 수정할 수 있다.
가방의 시작 아이템과 상점 진열은 모두 같은 ItemData를 사용한다.

희귀도는 일반, 고급, 희귀, 영웅, 전설의 5단계다. 현재 전설은 상점 추첨에서
완전히 제외된다.

## 라운드별 상점 확률

`Assets/_Project/Data/Shop/ShopRarityTable_Default.asset`을 선택하면 Inspector에서
1~12라운드의 일반/고급/희귀/영웅 확률을 직접 수정할 수 있다. 각 라운드의 합계는
100을 권장한다. 1라운드는 `70/20/10/0`, 10라운드는 `15/25/40/20`으로 설정되어
있다. 먼저 희귀도를 확률로 뽑은 다음, 해당 희귀도의 ItemData 중 하나를 무작위로
고르므로 같은 아이템 종류가 여러 칸에 진열될 수 있다.

플레이를 시작하면 20 골드를 보유한다. 아이템을 가방 또는 보관함 안에 정상적으로
놓았을 때만 구매 가격이 차감된다. 보관함 밖의 잘못된 위치에 놓으면 구매가
취소되고 골드는 유지된다.

각 진열 슬롯은 한 번만 구매할 수 있다. 구매한 자리는 `구매 완료`로 비워지며,
새로고침이나 다음 라운드에는 이미 보유한 아이템도 다시 등장할 수 있다.
같은 종류가 여러 슬롯에 진열되면 슬롯별로 한 번씩 구매할 수 있다.

각 슬롯은 진열될 때 희귀도/아이템 종류와 별개로 10% 확률로 할인된다.
할인 슬롯은 원가에 빨간 취소선을 긋고 빨간 할인가와 `Sale!`을 표시한다.
할인가와 재판매 가격은 모두 ItemData 원가를 기준으로 `(원가 + 1) / 2`를 정수로
계산한다. 예: 1G→1G, 3G→2G, 5G→3G. 할인 구매한 아이템의 재판매가에도
같은 원가 기준을 적용한다. 씬의 `Backpack Prototype` Inspector에서 `Sale Chance`
값을 바꿀 수 있다 (`0.1` = 10%).

## 바로 다음 작업

- 드래그 감각과 회전 규칙을 직접 플레이하며 확인
- 가방 UI와 아이템 View를 프리팹 또는 재사용 가능한 컴포넌트로 정리
- 방어구, 회복 소모품, 장신구의 전투 효과 추가
- 인접 배치에 따른 전투 스탯 보정과 시너지 추가
- 라운드별 적 데이터와 난이도 설계
- 구매 및 판매 행동에 대한 되돌리기 지원

## 기본 자동 전투

ItemData의 `Weapon Stats`에서 다섯 가지 무기 기본 스탯을 수정할 수 있다.
공격력은 피해량, 쿨타임은 초, 명중률/치명타 확률/치명타 피해는 퍼센트로 입력한다.
치명타 피해 200은 일반 피해의 2배를 뜻한다. 이 데이터는 Weapon 분류에만 적용한다.

| 무기 | 공격력 | 쿨타임 | 명중률 | 치명타 확률 | 치명타 피해 |
|---|---:|---:|---:|---:|---:|
| 훈련용 검 | 5 | 2초 | 90% | 10% | 200% |
| 철 단검 | 2 | 1초 | 95% | 15% | 180% |
| 쌍도끼 | 8 | 3초 | 85% | 20% | 200% |
| 화염 지팡이 | 12 | 3.5초 | 90% | 10% | 220% |

전투 시작 시 가방의 아이템 ID, 점유 칸, 위치, 회전, 기본 스탯을
`CombatLoadoutSnapshot`으로 복사한다. 보관함 아이템은 복사하지 않는다.
각 무기는 복사한 기본 스탯과 별도로 `RuntimeWeaponStats`를 가진다.
향후 버프와 시너지는 이 실제 스탯에 적용하며, 원본 SO는 변경하지 않는다.
다음 전투를 시작하면 실제 스탯과 쿨타임은 새로 만들어진다.

첫 공격은 무기 자신의 쿨타임이 지난 후 발생한다. 이후에도 무기마다 독립적으로
공격한다. 명중을 먼저 판정하고, 적중했을 때만 치명타를 판정한다.
빗나가도 쿨타임을 소비한다. 일반 명중은 공격력만큼, 치명타는
`공격력 × 치명타 피해 / 100`만큼 피해를 주며, 소수 피해를 유지한다.
같은 시각의 공격은 플레이어 무기부터 안정된 순서로 처리하고 사망 후 공격은 중단한다.

프로토타입 플레이어의 기본 체력은 40이다. 상대는 체력 30의 고블린으로,
3×3 가방의 `(1, 0)`에 1×2 몽둥이를 세로로 배치했다. 몽둥이는 공격력 5,
쿨타임 2초, 명중률 100%, 치명타 확률 0%, 치명타 피해 200%를 사용한다.
현재 모든 라운드에서 같은 고블린을 사용한다.

`Assets/_Project/Data/Enemies/Enemy_Goblin.asset`에서 적의 이름, 체력,
가방 크기와 아이템 배치 목록을 수정한다. `Enemies/Items/Item_GoblinClub.asset`은
적 전용 ItemData이며 플레이어 상점 카탈로그에 포함하지 않는다. 적이 플레이어와
동일한 아이템을 사용할 필요는 없고, 아이템의 형태·기본 스탯 데이터 구조만 공유한다.
겹치거나 가방 밖으로 나간 적 아이템 배치는 전투 시작 시 거부한다.
씬의 `Backpack Prototype > Combat Prototype`에서 플레이어 체력과 제한 시간(기본 120초)을 조절한다.

## 상점과 전투 화면 분리

하나의 Unity 씬 안에 `Shop Screen`과 `Battle Screen`을 따로 두고 전환한다.
골드·라운드·진행 상태는 `PrototypeRunState`가 보관하며, 원래 가방/보관함과 배치 정보는
화면 전환 중에도 유지된다. 전투 화면은 양쪽 `CombatantSnapshot`을 받아
읽기 전용 가방을 새로 그린다. 상점의 가방 View를 옮기거나 전투 연출에 사용하지 않는다.

`PrototypeBattleController`는 전투 계산과 시간 진행을 담당하고,
`PrototypeBattleScreen` 및 `PrototypeBattleBagView`는 체력/쿨타임/공격 효과를 표시한다.
양쪽 모두 자기 가방에 있는 무기의 목록으로 공격하므로 적에게 여러 무기를 배치할 수도 있다.
전투 종료 시 결과만 진행 관리 코드로 전달하며, 승리 후 다음 라운드 상점이나
패배 후 같은 라운드 상점으로 돌아간다. 전투용 스탯을 변경해도 원래 SO와 상점 배치는 바뀌지 않는다.

전투 및 결과 화면에서는 구매, 판매, 배치, 회전, 새로고침을 잠근다.
승리 후 다음 라운드로 이동할 때만 라운드 수입을 한 번 지급한다.
패배/시간 초과 후 다시 준비하면 라운드·골드는 유지되며 재도전 시 체력은 회복된다.
12라운드 승리 후에는 완료 상태가 되고 13라운드로 넘어가지 않는다.
이번 버전은 무기 기본 공격만 처리한다. 방패·부적·물약의 효과와
화염 지팡이의 화상 등은 아직 적용하지 않는다.

## 아이템 주기 표시와 툴팁

현재 사용 주기가 있는 무기는 낮은 채도의 바탕색 위로 원래 색이 아래에서 위로
차오른다. 여러 칸이나 회전한 아이템도 전체 높이를 기준으로 한 번에 차오르며,
모양의 빈 칸은 유지한다. 아이템을 사용하면 원래 색의 채움이 0으로 돌아간다.
사용 주기가 없는 방패·장신구 등은 평소 색을 유지한다. 하단 쿨타임 게이지는 제거했다.

툴팁은 상점·가방·보관함·양쪽 전투 가방에서 공통으로 사용한다.
이름과 희귀도를 위에 표시하고, 첫 줄은 공격력/사용 주기/명중률,
둘째 줄은 치명타 확률/치명타 피해를 아이콘과 함께 표시한다.
전투 중에는 실제 스탯을 계속 갱신하며, 기본 SO에는 영향을 주지 않는다.
화면 가장자리에서 툴팁 위치를 보정하고, 드래그나 화면 전환 시 숨긴다.
툴팁은 마우스 클릭/드래그를 가로막지 않는다.

ItemData의 `Effect Description`에 추가 효과 설명을 입력하면 일반 `Description`과
함께 툴팁 아래쪽에 표시한다. 이 필드는 설명용 텍스트이며 전투 효과의 실행 코드는
별도로 구현해야 한다. 공격력·사용 주기·명중률·치명타 확률은 UI 도형으로 그린다.
치명타 피해는 제공된 원본 이미지의 투명도를 그대로 사용하며,
`CriticalDamageWhite` 머티리얼로 RGB만 밝은 단색으로 표시한다.

## 축소된 가방과 자유 보관함 / 전투 일러스트 자리

상점 가방은 기존 444×444에서 324×324로 줄였으며, 논리적인 6×6 칸은 그대로다.
보관함은 610×208로 넓혔다. 가방·드래그·보관함이 같은 다중 칸 모양과 색을 사용하며,
보관함으로 옮기거나 다시 꺼낼 때 회전 방향도 유지한다. 위치는 자유 좌표이고
칸 맞춤·충돌 검사·개수 제한이 없으므로 서로 겹쳐 놓을 수도 있다.
경계에서는 아이템 전체 크기를 기준으로 위치를 보정해 제목과 테두리를 침범하지 않는다.

전투 가방은 최대 228×228이며, 양쪽 가방 아래에 `Player Character Illustration`과
`Enemy Character Illustration` 자리를 예약했다. 일러스트는 비워 두고 옅은 프레임만 표시한다.
이름은 가방 아래·일러스트 위에 표시하며, 일러스트 아래에 실제 체력바를 둔다.
큰 배경 프레임은 가방만 감싸고, 일러스트와 체력바는 그 밖에 배치한다.
상단에는 크게 라운드와 진행 시간만 표시하고, 전투 결과 문구는 종료 시에만 나타난다.
방어도 배지는 체력바 왼쪽의 하늘색 방패이며, 양수일 때만 숫자와 함께 표시한다.
현재 방어도 전투 로직은 없으므로 실제 전투에서는 배지를 숨긴다.

상점의 클릭 정보 패널과 하단 상태 안내 바는 제거했다. 정보는 마우스 툴팁으로 확인하며,
상점 툴팁의 `기본 스탯` 문구도 표시하지 않는다. 구매·배치 등의 진단 메시지는
화면에 띄우지 않고 Unity Console에서 확인할 수 있다.
