# 공유 경험치와 캐릭터 레벨

## 플레이 흐름

- 메인에서 시작한 런의 클리어 또는 최종 게임 오버 시 경험치를 계정의 공유 잔액에 지급한다.
- 라이프가 남아 같은 라운드를 재도전하는 패배, 일반 라운드 승리, 메인 복귀·결과 화면 재열기는 별도 경험치를 지급하지 않는다.
- 캐릭터 탭에서 미리보는 캐릭터의 현재 레벨·능력치와 레벨업 비용을 확인한다. 다음 레벨 능력치 미리보기는 표시하지 않는다.
- 둥근 사각형 버튼의 위쪽에 `레벨 업`, 아래쪽에 경험치 아이콘과 비용을 표시한다. 한 번 누르면 해당 캐릭터만 한 레벨 성장하고 필요한 경험치를 소비한다. 경험치가 부족하거나 캐러셀 이동 중이면 버튼을 비활성화한다.
- 공유 잔액은 캐릭터·메인·스테이지 탭 공통 왼쪽 상단의 둥근 반투명 패널에 경험치 아이콘과 숫자로 표시한다. 아이콘은 연두색 별 중앙에 검정 테두리·흰색 채움의 둥근 EXP 문양을 크게 겹친다. 잔액과 비용에 동일한 아이콘을 사용한다. 캐릭터 패널과 메인 콘텐츠 안에 잔액을 중복 표시하지 않는다. 탭은 화면 하단에 배치하며, 레벨업 성공 직후 상단 잔액을 갱신한다.
- 다른 캐릭터에 투자해도 출전 캐릭터 선택을 자동으로 바꾸지 않는다. 출전 캐릭터는 기존 `선택` 버튼으로 확정한다.
- 캐릭터별 레벨은 독립적이며, 사용하지 않은 경험치는 캐릭터 사이에 공유한다. 부분 투자 없이 다음 레벨의 비용을 한 번에 소비한다.

## 경험치 보상

각 StageData의 `Clear Experience`를 클리어 보상 100%로 사용한다. 초안 보상은 다음과 같으며 Inspector에서 변경할 수 있다.

| 스테이지 | 클리어 경험치 |
| --- | ---: |
| 1 | 100 |
| 2 | 200 |
| 3 | 400 |
| 4 | 800 |
| 5 | 1,600 |

| 런 종료 조건 | 지급 비율 |
| --- | ---: |
| 최종 라운드 승리 | 100% |
| 1~4라운드에서 라이프 소진 | 10% |
| 5~8라운드에서 라이프 소진 | 25% |
| 9~12라운드에서 라이프 소진 | 50% |

`최종 지급 경험치 = floor(클리어 경험치 × 지급 비율)`이다. 과거 최고 도달 라운드 대신 이번 런이 끝난 라운드를 사용한다. 보상 기준값은 스테이지 입장 시 복사하므로 플레이 도중 SO를 편집해도 해당 런의 정산은 변하지 않는다.

최고 클리어 스테이지에 따른 경험치 감액은 없다. 이미 클리어한 낮은 스테이지를 반복해도 같은 기준으로 지급한다. 최초 클리어의 별도 경험치 보너스는 없다. 다음 스테이지 입장 해금 규칙은 기존대로 유지한다.

결과 화면에 획득 경험치를 표시하고, 메인 탭들의 공통 상단에 공유 잔액을 표시한다. Prototype_Backpack 씬을 직접 실행한 개발용 런은 기존 정책대로 영구 진행도·경험치를 저장하지 않는다. 메인에서 시작한 런과 재도전은 정상 정산한다.

## 성장 데이터

- `Assets/_Project/Data/ExperienceTable_Default.asset`: 기본 레벨업 비용 100, 비용 배율 1.25.
- CharacterData의 `Experience Table`에 테이블 SO를 연결한다. 알렌과 세레나는 같은 테이블을 참조하지만, 필요하면 서로 다른 테이블을 연결할 수 있다.
- 새 테이블은 `Create > Backpack AutoBattle > Experience Table`에서 생성한다.

현재 레벨이 L일 때 다음 레벨 비용은 `floor(기본 비용 × 비용 배율^(L−1))`이다. 이전 단계에서 버림한 비용에 다시 배율을 곱하지 않는다. 기본 테이블의 비용은 100 / 125 / 156 / 195 / 244 / 305 ... 이다. 경험치 잔액과 비용에는 64비트 정수를 사용하고, 표현 가능한 비용 범위를 넘으면 추가 소비를 허용하지 않는다.

능력치는 `floor(캐릭터 기본 능력치 × 1.1^(L−1))`로 계산한다. 기본 체력 50·공격력 10일 때 1레벨 50/10, 2레벨 55/11, 3레벨 60/12, 5레벨 73/14, 11레벨 129/25다. 매 레벨의 버림 결과를 다음 계산의 기초로 사용하지 않는다. SO의 기본 수치 자체도 변경하지 않는다.

레벨이 반영된 체력·공격력은 스테이지 입장 시 확정한다. 무기, 방패, 숫돌, 화상·중독·가시·흡혈은 기존 능력치 계수 구조를 통해 해당 확정값을 사용한다. 인스테이지 툴팁에는 계수 대신 최종 수치를 유지한다. 스테이지 내부에서는 레벨업을 허용하지 않는다.

## 저장과 검증

- `player-progress.json`의 `sharedExperience`와 캐릭터 ID별 `characters[{characterId, level}]`에 경험치와 레벨을 저장한다.
- 버전 1의 선택 캐릭터·선택 스테이지·진행 기록은 보존하며, 경험치 0과 캐릭터별 1레벨을 기본값으로 사용한다. 다음 저장에는 현재 저장 버전을 적용한다.
- 레벨업 비용 차감과 캐릭터 레벨 변경을 하나의 파일 교체로 저장한다. 저장에 실패하면 레벨과 잔액을 변경하지 않고 캐릭터 화면에 오류를 표시한다.
- 결과 정산은 전투에서 종료 결과로의 한 번뿐인 상태 전환에서 수행한다. 경험치와 클리어 기록을 같은 저장 내용에 포함해 결과 확인·복귀·재시작으로 중복 지급하지 않는다. 결과 저장 실패는 결과 화면에 안내한다.
- 이전 버전과 마찬가지로 읽을 수 없는 파일·더 최신 버전은 보존하며, 자동 테스트는 별도의 프로필 파일을 사용한다.

EditMode에서 비용·능력치 계산, 보상 구간과 버림, 캐릭터별 소비, 저장 마이그레이션을 검증한다. PlayMode에서 실제 게임 오버·반복 클리어 정산, 캐릭터 선택과 별개의 투자, 재실행 후 유지, 전투 반영과 저장 실패 시 소비 취소를 검증한다.
