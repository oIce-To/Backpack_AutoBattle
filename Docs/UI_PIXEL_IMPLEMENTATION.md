# 인스테이지 상점 픽셀 UI 적용

2026-11-15 · 디자인 v3의 첫 Unity 적용본

## 직접 확인하기

1. Unity 6000.3.17f1에서 `Assets/Scenes/Prototype_Backpack.unity`를 연다.
2. Game 뷰를 **16:9**, 가능하면 **1920×1080** 또는 **1280×720**으로 설정하고 Play를 누른다.
3. 상점 상품을 가방/보관함으로 드래그하고, 회전·판매·상품 잠금을 확인한다.
4. **적 정보**를 열어 적 이름·체력·아이템을 확인한다. 닫기/배경 클릭/ESC로 돌아온다.
5. **전투 시작** 후 다음 라운드의 상점으로 돌아와 정보가 갱신되는지 확인한다.

메인 화면에서 시작하려면 `MainMenu` 씬 → 캐릭터/장비 선택 → 스테이지 입장 순서로 진입한다. 씬에 디버그 라운드 진행이 활성화되어 있으면 기존 테스트용 다음 라운드 버튼도 표시된다.

## 적용 범위

- 짙은 남색 화면과 상단 스테이지/라운드 정보.
- 왼쪽 상품 카드, 중앙 가방과 자유 보관함, 오른쪽 출전 캐릭터·적 정보·전투 시작.
- 계단형 모서리, 황동 장식, 갈색 가방 프레임, 음영이 들어간 빈 칸.
- 금색 주 행동 버튼과 청록색 보조 버튼, 호버/눌림/비활성 상태.
- 적 정보 팝업과 상대 가방에 같은 스타일 적용. 기존의 모달 입력 차단과 닫기 동작 유지.

기존 드래그 판정과 아이템 크기에 맞춰 플레이어 가방은 **324×324 / 54px 간격 / 48px 칸**, 보관함은 **610×208**을 유지했다. HTML 시안의 가방 표시 크기와는 차이가 있다. 기준 해상도는 1280×720이며 CanvasScaler로 화면 크기에 대응한다. 비정수 배율에서는 픽셀 경계의 화면상 굵기가 달라질 수 있다.

메인 메뉴·전투·결과 화면의 전체 스타일은 이번 적용 범위에 포함하지 않는다. 실제 아이템/캐릭터 데이터와 원본 아트를 사용한다.

## 후속 디자인 피드백 반영

- **가방:** 빈 칸과 외곽을 갈색 계열로 통일. 손잡이, 바느질, 가죽 벨트, 황동 버클과 모서리 장식을 추가했다. 플레이어 가방과 적 정보 팝업의 가방에 함께 적용한다. 기존 배치 좌표와 판정 영역은 유지한다.
- **캐릭터:** 일러스트 뒤의 패널을 투명하게 만들고 표시 영역을 172×272에서 252×354로 확대했다. 이름과 오류 메시지는 별도 공간에 유지한다.
- **상점:** 목재 판자, 나뭇결, 세로 기둥, 금속 못과 간판 아래 홈을 추가했다. 상품 카드도 따뜻한 갈색 음영으로 바꿨다.
- **골드:** 코인 도입 작업을 철회하고 모든 화면의 G 문자열, 공백, 가격 정렬과 판매 금액 배치를 도입 전 상태로 복원했다. 전용 금화 컴포넌트와 메타 파일을 삭제했다.
- **합성선:** 아이보리/금색 상태 구분과 완만한 곡률, 중앙 픽셀 마름모를 유지한다. 도트와 점선은 제거하고 가장자리가 부드러운 연속 선으로 그린다. 양 끝은 둥근 끝처리로 정리했다. 합성 판정, 잠금, 호버 조건과 입력 차단은 변경하지 않았다.

장식은 `PrototypeFantasyTrim.cs`, 합성 연결선은 `PrototypeFusionOverlay.cs`에서 조정한다. 골드 복원 및 연속 곡선 검증 자료는 `Logs/UISmoothFusion`에 저장한다. 테스트마다 별도 프로필/설정 경로를 지정한다.

이전 목재·가죽 적용본은 전체 PlayMode 112/112를 통과했다 (`Logs/PixelUIFantasy/final.xml`). 현재 할인 가격과 판매 가격 테스트는 코인 도입 이전의 G 문자열 검증으로 복원했다.

G 표기 복원 및 연속 곡선 적용본도 전체 PlayMode **112/112 통과** (`Logs/UISmoothFusion/tests.xml`). 상점·판매 화면과 흰색/금색 합성선의 실제 Unity 캡처를 확인했다. 골드 갱신 함수와 판매 문구는 코인 도입 이전 코드와 동일함을 대조했다.

## 수정 위치

- `PrototypePixelSkin.cs`: 공통 색상과 Point 필터 / 9-slice 픽셀 프레임 생성.
- `PrototypePixelButtonFeedback.cs`: 버튼 입력 상태와 눌림 표현.
- `BackpackPrototypeController.cs`, `BackpackPrototypePreparationStyle.cs`: 상점/가방/보관함 배치와 헤더.
- `PrototypePreparationPanel.cs`: 캐릭터와 적 정보 팝업.

## 피드백 포인트

우선 실제 플레이 화면에서 글자·상품·가방 크기, 프레임의 굵기, 캐릭터 크기, 버튼의 구분을 확인한다. 예: “상품명이 작다”, “가방 테두리를 더 얇게”, “전투 시작 버튼을 더 밝게”. 그 피드백을 반영한 뒤 같은 스타일을 전투 HUD와 결과 화면에 확장한다.

## 검증 기록

- Unity 6000.3.17f1 컴파일 완료.
- 별도 프로필에서 전체 PlayMode **112/112 통과**. 결과: `Logs/PixelUI/playmode-isolated.xml`.
- 새 검증은 실제 버튼 이벤트로 눌림 중 클릭 영역 유지, 팝업의 배경 입력 차단, 닫은 후 전투 시작을 확인한다.
- 준비 화면과 적 정보 팝업을 실제 Unity Canvas에서 1280×720로 캡처하고 확인했다. 캡처: `Logs/PixelUI/PixelPreparation.png`, `PixelEnemyPreview.png`.
- 캡처 유틸리티는 작은 배치 테스트 Game 뷰의 글자가 확대되지 않도록 캡처 중 Canvas 배율을 1로 설정하고 종료 시 복원한다.

첫 전체 테스트는 기존 로컬 진행도를 참조해 메인 메뉴 능력치 검증 2개가 실패했으며, 실행 중 로컬 `player-progress.json`도 갱신됐다. 실행 전 원본이 없어 임의로 복원하지 않았다. 당시 현재 파일과 `.bak`의 사본을 `Logs/PixelUI/local-profile-after-first-run.json` 및 `.bak`에 보존했다. 이후 테스트는 `BACKPACK_PROFILE_PATH`와 `BACKPACK_SETTINGS_PATH`를 지정해 로컬 진행도와 분리했다. 재실행 시에도 이 두 경로를 별도 테스트 파일로 설정해야 한다.
