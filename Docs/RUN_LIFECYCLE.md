# 라이프, 런 종료, 재시작

## 현재 플레이 규칙

- 기본 시작 라이프는 **3**이다. 씬의 Backpack Prototype → Run Rules → Starting Lives에서 변경할 수 있다.
- 체력(HP)과 라이프는 별개의 수치다. 전투에서 패배하면 라이프만 1 차감한다.
- 라이프가 남으면 결과 버튼으로 상점에 돌아가 **같은 라운드**를 재도전한다. 골드, 가방, 보관함, 잠긴 상품은 유지하고 추가 수입/무료 리롤은 지급하지 않는다.
- 기존 규칙대로, 살아서 상점에 돌아오는 패배에서도 전투 시작 시 예약된 합성을 처리한다.
- 라이프가 0이면 게임 오버다. 상점 복귀·구매·리롤·라운드 건너뛰기·다음 전투를 막고 런 결과 화면을 표시한다.
- 마지막 라운드에서 이기면 스테이지 클리어다. 13라운드 진입이나 추가 라운드 수입은 없다.
- 게임 오버/최종 클리어에서는 더 이상 상점에 진입하지 않으므로 합성 예약을 실행하지 않는다. 재료는 종료 시점의 가방에 남아 있다가 새 런에서 초기화된다.
- 전투 60초부터 광폭화가 적용된다. 60초에 받는 피해 +10%, 이후 3초마다 +10%p씩 합산하여 87초부터 +100%가 된다. 플레이어가 받는 일반 공격·화상·중독·가시·기타 모든 피해에 방어도 흡수 전 한 번 적용한다. 적이 받는 피해와 회복량은 바뀌지 않는다.
- **90초에 도달하면 체력이 남아 있어도 강제 패배**하고 라이프 1을 차감한다. 정확히 90초인 공격·지속 피해·회복보다 강제 패배가 우선한다. 체력을 0으로 만들거나 가짜 피해를 통계에 기록하지 않는다. 남은 라이프에 따라 같은 라운드 재도전/게임 오버로 이어진다.
- 플레이어 상태 영역에 광폭화 아이콘과 중첩을 표시하고, 툴팁은 현재 받는 피해 증가율만 설명한다. 전투 시간에서 파생되는 상태여서 아이템으로 부여·해제할 수 없으며 전투마다 초기화한다.
- 저수준 시뮬레이션은 90초보다 이른 명시적 테스트 제한의 Draw 결과를 계속 지원한다. 이 테스트 경로의 무승부는 라이프를 차감하지 않는다. 실제 스테이지의 90초 종료는 Draw가 아닌 Defeat다.

준비 화면과 전투 화면 우측 상단에 `라이프 현재 / 시작`을 표시한다. 1 이하일 때 빨간색으로 강조한다. 일반 패배에는 `패배 · 라이프 -1`을 표시한다.

## 전투 배속과 일시정지

- 상단 라운드·시간 표시 아래에서 `0.5× / 1× / 2× / 3×`를 선택한다. 선택한 배속을 강조 표시한다.
- 일시정지 버튼은 평소 두 개의 세로 막대이며, 정지 중에는 재생 삼각형으로 바뀐다. 정지 중 배속을 바꾸어도 바로 재생하지 않는다. 재생을 누르면 선택한 배속으로 이어진다.
- 배속은 전투 시계에만 적용한다. 아이템 쿨타임, 지속 피해, 광폭화와 강제 패배는 모두 전투 시간을 기준으로 진행한다. 예를 들어 3배속에서는 실제 20초에 전투 60초, 실제 30초에 전투 90초가 된다.
- 화면의 전투 시간과 아이템 툴팁 수치는 전투 기준이다. 3배속에서도 쿨타임 1.82초는 1.82초로 표시한다. 배속 전환 시 진행 중인 쿨타임이나 시간이 초기화되지 않는다.
- 일시정지 중에는 전투 시간·공격·상태 피해·광폭화·90초 종료가 모두 멈춘다. 툴팁과 화면 조작은 계속 사용할 수 있으며, 피해 숫자와 공격 강조의 표시 시간은 실제 시간을 따른다. Unity 전역 `Time.timeScale`을 변경하지 않는다.
- 매 전투 진입 시 **1배속·재생 상태**로 시작한다. 다음 라운드, 같은 라운드 재도전, 새 런 모두 직전 전투에서 선택한 배속을 이어받지 않는다. 전투가 끝나면 배속 버튼을 숨기고 결과·통계 버튼을 표시한다.
- 추후 설정 화면에서 유저가 기본 배속을 선택할 수 있도록 확장할 예정이다. 현재는 `PrototypeBattleController.DefaultPlaybackSpeed`의 1배속을 전투 시작 시 적용하며, 기본 배속 설정 UI와 저장 기능은 아직 추가하지 않았다.

## 결과 화면

클리어/게임 오버 결과 화면에서 스테이지, 완료/도달 라운드, 남은 라이프, 승리·패배 횟수, 누적 전투 시간을 보여준다. 남은 골드는 결과 화면에 표시하지 않는다. 내부 종료 스냅샷의 골드 기록은 유지하지만 영구 재화 보상으로 지급하지 않는다.

일반 승패와 런 종료 결과에서 `전투 통계`를 열어 직전 전투의 아이템별 실제 피해/회복/방어량을 확인할 수 있다. 기록 규칙은 [아이템별 전투 통계](COMBAT_STATISTICS.md)를 참고한다.

`같은 스테이지 다시 시작` 버튼은 씬을 다시 불러오거나 프로젝트 에셋을 변경하지 않는다. 다음 런 전용 데이터를 새로 만든다.

- 1라운드, 시작 골드, 설정된 시작 라이프, 통계/아이템 인스턴스 번호
- 기본 6×6 가방과 시작 아이템 3개, 원래 배치/회전
- 빈 보관함, 초기화된 선택/드래그/툴팁
- 새 상점 상품: 이전 상품의 구매 여부, 잠금, 할인 추첨 상태를 넘기지 않음
- 초기화된 합성 잠금·예약·연출
- 해제된 이전 전투 이벤트와 제거된 이전 전투 아이템/상태 아이콘
- 새 스테이지 진입 시점의 캐릭터 능력치 스냅샷

상품 종류나 할인 결과는 새 추첨에서 우연히 같을 수 있다. 이를 ‘이전 잠금/할인이 유지됐다’고 보지는 않는다.
개발용 다음 라운드 버튼, 미완성 회복 물약, 아이템 카탈로그, 디버그 적/스테이지 설정은 유지한다.

## 메인 화면 연결 지점

역할을 다음과 같이 분리했다.

1. `PrototypeRunState`: 라이프·전투 결과·통계·런 종료 판정. UI나 씬 이동에 의존하지 않는다.
2. `PrototypeRunResult`: 종료 시점의 **불변 스냅샷**. 다음 런을 시작해도 이전 결과가 바뀌지 않는다.
3. `PrototypeRunResultScreen`: 결과 표시와 재시작 요청만 담당한다. 라이프/보상/아이템을 직접 수정하지 않는다.
4. `BackpackPrototypeController`: 기존 준비/전투 흐름 연결과 새 런 초기화.

`RunEnded` 이벤트는 클리어/게임 오버가 확정될 때 한 번만 발행한다. 향후 진행 관리자에서 이 결과를 받아 클리어 기록·해금·외부 보상을 처리할 수 있다. 지금은 저장이나 영구 보상을 임의로 지급하지 않는다.

`RestartRequested`는 선택적인 화면 이동 연결점이다. 구독자가 없으면 프로토타입의 공통 `TryRestartRun()`으로 새 런을 시작한다. 구독자가 있으면 자동 재시작을 하지 않고 구독자에게 제어를 넘긴다. 메인 화면을 만들면 그 구독자에서 메인으로 이동하거나 재도전을 선택하도록 연결하면 된다. 요청은 한 번만 전달되며 버튼을 잠가 중복 이동을 막는다.

`TryRestartRun()`은 종료된 런에서만 동작한다. 진행 중 실수로 호출하거나 재시작 버튼을 연타해 시작 아이템·골드가 중복 생성되는 것을 막는다. 외부 화면 이동 담당자도 필요하면 이 초기화를 명시적으로 호출할 수 있다.

## 확인 방법

1. 기본 씬을 Play하고 준비 화면 우측 상단의 `라이프 3 / 3`을 확인한다.
2. 패배하면 `라이프 2 / 3`과 `라이프 -1`을 확인한다. 상점으로 돌아와 같은 라운드/골드/아이템을 유지하는지 확인한다.
3. 라이프를 모두 잃으면 게임 오버 결과가 나오며 상점으로 돌아갈 수 없어야 한다.
4. 다시 시작을 누르면 1라운드/20G/라이프 3/시작 아이템 3개/빈 보관함이 되어야 한다(기본 설정 기준).
5. 마지막 라운드를 이기면 클리어 결과에서 다시 시작할 수 있어야 한다.
6. 개발용 다음 라운드와 미완성 아이템이 그대로 남아 있는지 확인한다.

게임 오버를 빠르게 보려면 Play 전에 Starting Lives를 1로 줄이고 더 강한 시험 스테이지/적을 지정해볼 수 있다. 확인 후 시작 라이프 3과 원래 스테이지/디버그 적 설정으로 복구한다.

자동 테스트는 패배 중복 차감 방지, 광폭화 경계 시각·모든 피해 경로·90초 강제 패배, 클리어 중복 처리 방지, 양쪽 종료 후 재시작, 상점/가방/보관함/합성 상태 초기화, 외부 능력치 재캡처와 화면 이동 콜백 분리를 검증한다.
